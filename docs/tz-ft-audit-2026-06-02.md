## 2. Краткий вывод

Проект находится ближе к опытно-стендовой версии, чем к production. Сильная часть - контур ELMO/угловой скорости: выделенный пакет `nc3-elmo-machines`, UDP/XState transport, атомарный poll, сценарии, протоколирование и тесты. После `npm ci` тесты пакета проходят: 59/59.

Основные blockers до production:

1. БЕП не доведен: process start сломан (`python` без `C:\NC3\nc3_bep.py`), топики high-level flow и базового шлюза не согласованы, `BEP Calibration` отключен, пересчета емкости в зазор по ТЗ нет.
2. Датчик давления Festo SPAU-P10RW не интегрирован: в мониторинге сейчас статическая карточка, `analogParam` для ELMO full-state не задан, нет порогов и interlock-поведения.
3. Автоматический наклон БУН не реализован как backend state machine: нет последовательности `тормоз выкл -> GO -> достижение -> тормоз вкл -> привод выкл`, критерия достижения и timeout.
4. Поправка угла наклона по БЕП/круглограмме отсутствует: настройки хранят текст, но нет расчетной функции и связи с отображаемым углом.
5. Удаленное управление и технологический доступ не production-safe: нет отдельного клиента ПО УУ АПК, нет backend command gate, технологический режим разблокируется в браузере без проверки пароля.
6. Мониторинг частично демонстрационный: давление, момент двигателя, BEP values/status частично hardcoded или не имеют fresh/stale/error semantics.
7. Нет воспроизводимого production-развертывания: версии Node-RED palette nodes не зафиксированы, runtime-файлы/сценарии/настройки не имеют backup/restore регламента, внешние Python-шлюзы не входят в репозиторий.
