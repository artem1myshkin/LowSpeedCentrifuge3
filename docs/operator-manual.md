## Аннотация

Настоящее руководство описывает порядок работы оператора с программным обеспечением LowSpeedCentrifuge3 для управления низкоскоростной центрифугой НЦ-3/2: воспроизведение угловой скорости, инициализация и поиск нулевой метки привода, управление наклоном (Tilt Control), измерения зазора БЕП (Gap Control), управление сценариями (Scenario Manager), настройка параметров, ведение протоколов и просмотр журнала событий.

Руководство составлено по текущему состоянию кода `flows.json`, пакета `packages/nc3-elmo-machines`, файлов сценариев и проектной документации в каталоге `docs`, а также по документу "Рекомендации к разработке ПО для центрифуги с изменяемым направлением оси вращения НЦ-3/2".

Документ ориентирован на оператора установки. Низкоуровневые детали Node-RED, MQTT, UDP и внутренних функций приведены только там, где они объясняют видимое поведение интерфейса или влияют на безопасность работы со стендом.

## 1. Назначение программы

Программное обеспечение LowSpeedCentrifuge3 предназначено для операторского управления стендом НЦ-3/2 через веб-интерфейс Node-RED Dashboard 2.

Основные функции ПО:

- общий мониторинг состояния установки;
- ручное управление приводом ELMO внутренней оси;
- инициализация привода с поиском нулевой метки датчика угла;
- задание и воспроизведение угловой скорости;
- переключение диапазонов энкодера `high` и `low` (кнопка `БПП`);
- выполнение сценариев воспроизведения угловой скорости из файлов `.scn`;
- автоматическое и ручное протоколирование результатов;
- запись исходных данных положения по меткам времени контроллера ELMO;
- управление узлом наклона БУН (Tilt Control);
- просмотр и управление измерениями зазора БЕП (Gap Control);
- настройка общих и расширенных параметров, включая параметры контура скорости привода;
- ведение persistent-журнала событий;
- просмотр протоколов и построение графиков по data-файлам;
- режим удалённого управления с блокировкой команд неактивных клиентов и выделенной кнопкой аварийной остановки.

## 2. Условия выполнения программы

### 2.1 Программная среда

Для работы операторского интерфейса требуется:

- Node-RED с Dashboard 2;
- MQTT broker на `localhost:1883`;
- runtime-каталог `C:\NC3`;
- файл настроек `C:\NC3\settings.json`;
- каталоги `C:\NC3\protocols`, `C:\NC3\data`, `C:\NC3\scenarios`, `C:\NC3\logs`;
- внешние Python-шлюзы `C:\NC3\nc3_bun.py` и `C:\NC3\nc3_bep.py`, управляемые с вкладок `Tilt Control` и `Gap Control`;
- доступ оператора к Dashboard: `http://127.0.0.1:1880/dashboard`.

### 2.2 Аппаратные и сетевые компоненты

Текущий проект рассчитан на взаимодействие со следующими компонентами:

- привод ELMO: UDP `192.168.1.2:5001`, локальный порт ответов `5005`;
- БУН: внешний UDP-шлюз, целевое устройство `192.168.1.5:32767`;
- БЕП: внешний UDP-шлюз, целевое устройство `192.168.1.20:20001`;
- локальный MQTT broker для обмена с БУН/БЕП.

Оператору не требуется вручную формировать сетевые команды. Если связь с устройствами отсутствует, соответствующие состояния и ошибки анализируются по вкладкам интерфейса и журналу.

### 2.3 Подготовка оператора

Оператор должен знать:

- назначение режимов `Drive Init` (включая поиск нулевой метки), `STOP`, `JP`, `JV`, `БПП`;
- разницу между ручной работой и работой по сценарию;
- порядок открытия и закрытия протокола;
- порядок включения записи исходных данных;
- смысл диапазонов энкодера `high` и `low`;
- правила использования `STOP` и аварийной остановки, включая то, какая кнопка гарантированно работает при активном удалённом управлении (раздел 4.1);
- локальный регламент работы с удалённым управлением.

## 3. Общие принципы работы

### 3.1 Рабочие вкладки

В текущем Dashboard реализованы восемь страниц:

| Вкладка | Путь | Назначение |
|---|---|---|
| `Monitoring` | `/monitoring` | главный обзорный дашборд: статусы установки, упрощённое управление наклоном, протокол и запись, статус сценария |
| `Angular Speed Control` | `/velocity` | основная рабочая вкладка: привод ELMO, `Drive Init`, параметры движения, ручные команды, запись |
| `Tilt Control` | `/tilt` | управление узлом наклона БУН и скриптом обмена `nc3_bun.py` |
| `Gap Control` | `/gap` | измерения зазора БЕП, управление скриптом `nc3_bep.py`, конфигурация каналов |
| `Scenario Manager` | `/scenario-manager` | каталог и редактор файлов сценариев `.scn` |
| `Settings` | `/settings` | общие и расширенные параметры |
| `Journal` | `/journal` | persistent-журнал событий |
| `Protocols` | `/protocols` | просмотр файлов протоколов и data-файлов с графиками |

### 3.2 Состояние и команды

Интерфейс не является автономной страницей: данные поступают из Node-RED backend. При открытии вкладки UI отправляет запросы обновления (`reread`, `event_log_refresh`, `journal_refresh`, `scenario_catalog_refresh`) и получает текущее состояние из глобального контекста Node-RED.

Основные команды оператора проходят через общий слой удалённого управления. Кнопка может выглядеть доступной, но фактически выполняться только тогда, когда текущий клиент имеет право управления (`canControl`). При активном удалённом режиме локальный клиент становится преимущественно display-only, кроме отдельно разрешённых действий — подробнее в разделе 4.1.

### 3.3 Протоколирование

Протоколы создаются в `C:\NC3\protocols` в формате `protocol_<timestamp>.txt`. При включённой записи исходных данных создаётся связанный data-файл в `C:\NC3\data`.

Временной ряд data-файла строится по меткам `TM` контроллера ELMO и положению `PX`. Системное время компьютера для расчёта ряда не подставляется. Data-файл можно просмотреть и отобразить графически на вкладке `Protocols`.

### 3.4 Диапазоны энкодера

В ПО используются два диапазона:

- `high` — высокое разрешение, шаг 0,005°, рабочий диапазон по умолчанию от 1 угловой секунды/с до 20 °/с;
- `low` — низкое разрешение, шаг 0,2°, рабочий диапазон по умолчанию от 10 до 360 °/с.

Сценарный режим выбирает диапазон автоматически с порогом 20 °/с и гистерезисом 5 °/с. При смене диапазона сценарий выполняет: `STOP` → `MO=0` → параметры нового диапазона → полный `Drive Init` (с интегрированным поиском нулевой метки, раздел 7).

Ручное переключение кнопкой `БПП` возможно только при `MO=0` и `SO=0`. Иначе ПО показывает предупреждение "Смена разрешения невозможна: выключите двигатель (MO=0) и дождитесь остановки (SO=0)" и переключение не выполняется. После переключения статус инициализации сбрасывается в "не проведена", и перед рабочим движением требуется заново выполнить `Drive Init`.

## 4. Общие элементы интерфейса

### 4.1 Баннер удалённого управления и аварийная остановка

На вкладках `Monitoring` и `Angular Speed Control` (а также на других production-вкладках) используется общий баннер удалённого управления, который появляется, когда включён режим удалённого управления:

- "Удалённый режим включён" — статусная метка и, при наличии, текст последнего отказа в захвате управления;
- `Взять управление` — доступна удалённому клиенту, когда сессия управления не занята;
- `E-stop` — доступна локальному клиенту, когда управление отдано удалённому клиенту;
- `Выключить удалённое управление` — доступна локальному клиенту на вкладке `Settings`.

Если текущий клиент не имеет права управления, поля ввода и большинство кнопок блокируются. Наблюдение (значения, статусы, журнал, протоколы) остаётся доступным всегда.

**Важно про аварийную остановку.** В ПО есть несколько разных кнопок остановки, и не все они одинаково доступны при заблокированном UI:

- `E-stop` в баннере удалённого управления и кнопка `СТОП` в верхней строке вкладки `Monitoring` отправляют команду `emergency_stop`. Эта команда специально исключена из блокировки локального клиента и остаётся доступна независимо от того, кто владеет управлением.
- Кнопка `STOP` в блоке "Управление двигателем" на вкладке `Angular Speed Control` отправляет обычную команду `drive_stop` и подчиняется общей блокировке UI наравне с прочими командами. Если локальный клиент не имеет права управления, эта кнопка не сработает.
- Кнопка `Авария` в блоке сценария (вкладка `Angular Speed Control`) отправляет `scenario_emergency_stop` и также подчиняется общей блокировке UI.

Следствие для оператора: если требуется гарантированно остановить привод при активном удалённом управлении и заблокированном локальном UI, нужно использовать `E-stop` в баннере или `СТОП` на вкладке `Monitoring`, а не `STOP` на вкладке `Angular Speed Control`.

> **Место для скриншота:** общий баннер удалённого управления в активном и заблокированном состоянии.

### 4.2 Режимы ввода углов и скоростей

В интерфейсе используются несколько форматов ввода:

- DMS (`° ′ ″`) — градусы, минуты, секунды;
- десятичные градусы;
- радианы, где применимо (`Tilt Control`);
- тики энкодера, где требуется прямое управление приводом (`Angular Speed Control`).

В полях DMS минуты и секунды после потери фокуса приводятся к диапазону `0..59`. Для скорости градусы могут быть отрицательными, что соответствует обратному направлению вращения.

### 4.3 Блокировка во время активных операций

Во время активной записи, выполнения сценария, инициализации привода или удалённого управления часть кнопок блокируется для предотвращения конфликтующих команд.

## 5. Вкладка `Monitoring`

Вкладка `Monitoring` — главный обзорный дашборд оператора.

> **Место для скриншота:** общий вид вкладки `Monitoring`.

### 5.1 Строка состояния

Вверху страницы отображаются статусные чипы и кнопка аварийной остановки:

- `Иниц.: OK / … / Нет` — статус `Drive Init` (готов / выполняется / не проведена);
- `Готов: ДА / Нет` — готовность скорости: ротор набрал целевую скорость и удерживает её в допуске не менее заданного времени устойчивости;
- `Привод: Активен / Выкл` — состояние двигателя (`MO`);
- `Давление: OK (заглушка)` — индикатор контроля давления цепи пневмотормоза; в текущей версии ПО это фиксированная заглушка, реальный аналоговый вход подключается отдельно;
- `СТОП` (красная кнопка справа) — аварийная остановка (`emergency_stop`), доступна всегда независимо от режима удалённого управления (см. раздел 4.1).

Если `Drive Init` выполняется, под строкой состояния отображается прогресс-бар инициализации (см. раздел 7.4).

### 5.2 Схема НЦ-3 и текущее состояние

Левая панель — схема установки с индикаторами подсистем (БУН / БЕП / ELMO). Блок "Текущее состояние": угол наклона, скорость, позиция, разрешение (`high`/`low`), код ошибки `SR`.

### 5.3 Автоматический наклон

Центральная панель — упрощённый интерфейс БУН: текущий угол с индикатором тормоза, поле целевого угла и кнопка `Задать`, переключатель пневмотормоза, переключатель режима `Авто`/`Ручной`. Для полного управления наклоном используйте вкладку `Tilt Control`.

### 5.4 Протокол, запись и сценарий

Центральная и правая панели дублируют состояние протокола, записи и активного сценария из вкладки `Angular Speed Control`: путь к протоколу, статус и таймер записи, флаг записи исходных данных, кнопки `Открыть`/`Закрыть`/`Запись`; статус сценария, шаг, цель/факт, выдержка, кнопки `Старт`/`Пауза`/`Продолж.`/`Стоп`.

## 6. Вкладка `Angular Speed Control`

Основная рабочая вкладка оператора для управления приводом, задания скорости, работы со сценариями и протоколирования.

> **Место для скриншота:** общий вид вкладки `Angular Speed Control`.

### 6.1 Верхняя панель

В левой части заголовка расположены: кнопка `БПП`, чип текущего разрешения (`high`/`low`), чип статуса `Drive Init`, чип статуса сценария.

### 6.2 Блок "Управление двигателем"

- `Включить` — включает привод (`MO=1`); ПО ожидает готовности усилителя (`SO=1`) до 30 секунд;
- `Выключить` — выключает привод (`MO=0`); доступна, только пока `MO=1`;
- `STOP` — быстрая остановка (`ST`), замедление `QS` (по умолчанию 180 °/с²); подчиняется общей блокировке UI (см. раздел 4.1);
- `Drive Init` — запускает инициализацию привода с поиском нулевой метки; подробное описание — раздел 7.

Отдельной кнопки `HOME` в интерфейсе нет: поиск нулевой метки полностью выполняется внутри `Drive Init`.

Если после `Включить` усилитель не переходит в готовность (`SO=1`) за 30 секунд, ПО автоматически выполняет защитную остановку `ST` и `MO=0`; причину следует искать по статусу `SR` и журналу (раздел 15).

### 6.3 Блок статуса привода

- `MO` — `1` включён / `0` выключен;
- `SO` — `1` готов / `0` не готов;
- `MS` — `0` цель достигнута, `1` задание отработано (окно не выдержано), `2` движение, `3` привод выключен;
- `SR` — зелёный щит "Ошибок нет" / красный с чипами расшифровки кода ошибки;
- текущий диапазон `high`/`low` и цена тика.

### 6.4 Блок "Текущее состояние"

Живые данные: скорость (°/с и тик/с), позиция (тик и выбранный угловой формат), момент, диапазон и цена тика энкодера, фактически установленные `SP`/`AC`/`DC`/`JV`/`JP`.

### 6.5 Параметры движения

Поля скорости профиля (`SP`), ускорения (`AC`) и замедления (`DC`) в формате DMS с пересчётом в тики. Переключатель единиц: `° ′ ″` / `° дес.` / тики. Кнопка "Применить параметры" отправляет значения в привод. При смене диапазона физические значения (°/с, °/с²) сохраняются и пересчитываются в тики нового диапазона.

> **Место для скриншота:** блок "Параметры движения".

### 6.6 Ручные команды

Переключатель формата ввода: DMS / °дес. / тик.

- `JP` — вращение с контролем по скорости и положению;
- `JV` — вращение с контролем только по скорости;
- относительное перемещение (`PR`) — смещение от текущего положения;
- абсолютное перемещение (`PA`) — целевое положение в координатах привода.

Команды перемещения используют текущие параметры `SP`/`AC`/`DC`.

### 6.7 Блок протокола и записи

- `Открыть протокол` / `Закрыть протокол`;
- поле "Длительность записи", с (по умолчанию из настроек, 60 с);
- флаг "Запись исходных данных" — создаёт data-файл, связанный со строкой протокола;
- кнопка `Запись` — запускает серверный таймер на заданную длительность; кнопка блокируется на время записи;
- индикатор активной записи и обратный отсчёт.

При переходе между вкладками состояние активной записи и обратный отсчёт восстанавливаются из backend.

> **Место для скриншота:** блок протокола с открытым протоколом и активной записью.

## 7. Инициализация привода: `Drive Init` и поиск нулевой метки (Homing)

### 7.1 Зачем нужна инициализация

На стенде используются инкрементные датчики угла (ДУ), поэтому после каждого включения питания абсолютное нулевое положение неизвестно. Для определения нуля в ДУ предусмотрена уникальная нулевая метка, которая передаётся в контроллер ELMO по каналу `Index`. Процедура поиска нулевой метки (Homing) определяет смещение фактической нулевой метки от положения, принятого за нулевое в момент подачи питания, и заключается в повороте оси до захвата метки контроллером.

Нулевая позиция зависит от выбранной пары считывающих головок (`high`/`low`), поэтому `Drive Init` — и заложенный в него поиск нулевой метки — выполняется заново при каждой смене диапазона энкодера.

В текущей версии ПО отдельной кнопки `HOME` не существует: поиск нулевой метки выполняется автоматически как часть `Drive Init`, и во всех вариантах инициализации перед контрольным оборотом настраивается захват нулевой метки.

### 7.2 Ручной `Drive Init`

Запускается кнопкой `Drive Init` на вкладке `Angular Speed Control`. Двигатель должен быть уже включён и исправен (`SO=1`) — ручной режим не выполняет `MO=0`/`MO=1` и не меняет параметры диапазона.

Последовательность одной атомарной командной посылки:

1. `HM[3]=3` — источник нулевой метки: положительный фронт канала `Index` ДУ.
2. `HM[4]=2` — действие при обнаружении метки: ничего не делать (не останавливать движение).
3. `HM[5]=0` — при получении нулевой метки сбросить счётчик положения.
4. `HM[1]=1` — запустить поиск нулевой метки.
5. `SP`, `AC`, `DC` — скорость 5 °/с, ускорение и замедление 1 °/с².
6. `PR=<CA[18]>` — относительный поворот на один полный оборот планшайбы (в тиках текущего диапазона) от текущего положения.
7. `BG` — начать движение.

Пока идёт оборот, контроллер ELMO ищет нулевую метку по каналу `Index`; по её обнаружению `HM[1]` автоматически сбрасывается в `0`, а счётчик положения корректируется на найденное смещение (`HM[7]`). Если `HM[1]` не сбросился к концу оборота — либо на вход контроллера не поступает сигнал нулевой метки, либо неверно настроены `HM[3]`/`HM[4]`/`HM[5]`; такую ситуацию нужно передать ответственному персоналу.

Ручной `Drive Init` не блокирует опрос привода и другие вкладки интерфейса: ПО не ждёт физического завершения оборота внутри протокола обмена с ELMO, а определяет завершение самостоятельно по достижении приводом целевой позиции (с учётом допуска). Статус инициализации при этом отображается как "выполняется" до подтверждения по факту достигнутой позиции.

### 7.3 Полный `Drive Init`

Выполняется автоматически: при первом запуске сценария для диапазона без подтверждённой инициализации и при автоматической смене диапазона энкодера. Также используется, если вызывается с явным режимом `full`.

Полный `Drive Init` — это единая последовательность из пяти этапов, отправляемых с интервалом 2 секунды:

1. `ST` — быстрая остановка.
2. `VX; MO=0` — контрольное чтение текущей скорости и выключение двигателя.
3. Параметры нового диапазона: `OL[1]`, `CA[18]`, `S1[5]`, `KP[2]`, `SD`, `QS`, `VH[1]`, `VL[1]`, `VH[2]`, `ER[3]`, `ER[2]`, `TR[1]`, `TR[3]`, `TR[2]=100`, `TR[4]=100`.
4. Повторное подтверждение ключевых параметров: `OL[1]`, `CA[18]`, `VH[2]`, `SD`, `QS`.
5. Одна атомарная посылка: `SP`, `AC`, `DC` (5 °/с / 1 °/с² — как в ручном режиме) → `AF=0` (локальное управление) → `EC=0` (сброс кода последней ошибки) → `MO=1` (включение привода) → **ожидание `SO=1` до 30 секунд** → повторно `OL[1]`, `CA[18]`, `VH[2]`, `ER[3]`, `ER[2]` → `HM[3]=3`, `HM[4]=2`, `HM[5]=0`, `HM[1]=1` (настройка и запуск поиска нулевой метки) → `SP`, `AC`, `DC` → `PR=<CA[18]>` → `BG`.

Значения параметров диапазона (высокое/низкое разрешение): `OL[1]` 0/1, `CA[18]` 262144000/6553600 тик/оборот, `S1[5]` 40/40, `KP[2]` 5·10⁻⁷/1·10⁻⁵, `SD`/`QS`/`VH[1]`/`VL[1]` 131072000/3276800 (180 °/с²), `VH[2]` максимальная скорость по диапазону, `ER[3]`/`ER[2]` окна допустимой ошибки положения/скорости, `TR[1]`/`TR[3]` окна положения/скорости (0,01° / 0,5 °/с).

В отличие от ручного режима, полный `Drive Init` блокирует обмен с приводом на всё время выполнения: ПО активно опрашивает состояние движения (`MS`) до его завершения и только после этого освобождает канал для остальных команд и опроса.

### 7.4 Таймауты, прогресс и прерывание

- Ожидание готовности усилителя после `MO=1` (`SO=1`) — не более 30 секунд. При таймауте — автоматические `ST` и `MO=0`, `Drive Init` переходит в состояние "ошибка".
- Ожидание завершения одного оборота (включая поиск нулевой метки) — не менее 360 секунд (6 минут). Значение рассчитывается от заданных скорости и ускорения с запасом и подобрано так, чтобы не срабатывать раньше времени на реальном стенде даже при неполной скорости разгона.
- Прогресс-бар под строкой состояния (`Monitoring` и `Angular Speed Control`) отображает процент от фактического таймаута, а не фиксированное время — при увеличении таймаута в настройках прогресс-бар автоматически растягивается.
- Нажатие `STOP` или `Выключить` во время выполнения `Drive Init` немедленно останавливает и физическое движение, и прерывает инициализацию: статус переходит в "ошибка" с сообщением "Инициализация привода прервана оператором", в журнал добавляется соответствующая запись. Повторное выполнение `Drive Init` возможно сразу после этого.

Статус инициализации отображается чипом: `Инициализация` (выполняется), `Инициализация проведена`, `Инициализация не проведена`. Результат и ошибки фиксируются в журнале событий (`Drive Init: started / completed / failed`).

## 8. Сценарии воспроизведения угловой скорости (`Scenario Manager`)

### 8.1 Каталог сценариев

Сценарии хранятся в `C:\NC3\scenarios`. В репозитории есть базовые примеры: `high_resolution.scn`, `low_resolution.scn`, `range_switch.scn`. Изменения, сделанные оператором через UI на стенде, — runtime-данные, они не попадают в git автоматически.

### 8.2 Элементы вкладки

- `Обновить` — перечитать каталог сценариев;
- список `Файлы` — выбрать `.scn` файл;
- `+ Новый сценарий` — создать новый сценарий в редакторе;
- поле имени файла;
- таблица шагов: № / `Скорость, °/с` / `Выдержка, с` / удаление строки;
- `+ Добавить шаг`, `Удалить`, `Сохранить`.

Во время активного сценария редактирование и удаление блокируются.

### 8.3 Формат сценария

```text
=====
# Scenario file: example.scn
Name example
-------------------
# speed_deg_per_sec    hold_sec
5     30
22    45
30    60
=====
```

Первый столбец — целевая угловая скорость в °/с, второй — время выдержки в секундах после достижения допуска. Строки, начинающиеся с `#`, — комментарии.

### 8.4 Принцип выполнения сценария

1. Загружает выбранный файл; при закрытом протоколе открывает его автоматически.
2. Проверяет и нормализует шаги (скорость каждого шага обязана попадать в один из диапазонов энкодера).
3. Определяет нужный диапазон для каждого шага.
4. При необходимости смены диапазона: `STOP` → `MO=0` → полный `Drive Init` с параметрами нового диапазона (раздел 7.3).
5. Если инициализация для текущего диапазона не подтверждена — выполняет `Drive Init` перед шагом.
6. Задаёт целевую скорость команды `JP`.
7. Ожидает устойчивого достижения скорости (допуск, % и время устойчивости — из настроек).
8. Запускает выдержку и фиксирует результат в протокол.
9. Переходит к следующему шагу.

Таймаут достижения скорости = время разгона по `AC`/`DC` + резерв 10 секунд.

`Пауза` останавливает выполнение без сброса сценария. `Продолжить` запускает текущий шаг заново (остаток выдержки не восстанавливается). `STOP` завершает сценарий. `Авария` — аварийная остановка привода и отмена активной записи; сценарий можно продолжить после устранения причины (см. также раздел 4.1 про доступность этой кнопки при удалённом управлении).

## 9. Вкладка `Tilt Control`

Управление узлом наклона БУН и скриптом обмена `nc3_bun.py`.

> **Место для скриншота:** общий вид вкладки `Tilt Control`.

- Текущий угол в формате DMS, режим `Ручной`/`Авто`;
- поле целевого угла с переключателем формата DMS / deg / rad;
- `Установить` (зелёная) — отправить целевой угол в БУН (в угловых секундах);
- `Стоп` (красная) — остановить движение наклона с нормальным замедлением;
- `Release` — мгновенная остановка с отключением драйверов наклона (аварийное действие);
- `Нулевой угол` — текущий угол принимается за нулевой;
- `Больше` / `Меньше` — медленное движение в сторону увеличения/уменьшения угла;
- переключатель `Тормоз` — индикатор и управление пневмотормозом.

Тормоз внешней оси управляется через ELMO (выход `OL[2]`), а не напрямую через БУН. В автоматическом режиме переключатель тормоза блокируется.

Правая панель — скрипт обмена (`nc3_bun.py`): индикатор "Скрипт работает"/"Остановлен", последний статус `SYS_STATE` (hex), кнопки `Запустить`/`Перезапустить`/`Остановить`. Если нет валидных пакетов более 1,5 секунды, угол и состояние перестают обновляться — нажать `Перезапустить` или проверить сеть устройства.

## 10. Вкладка `Gap Control`

Мониторинг и управление измерительной системой зазоров БЕП.

> **Место для скриншота:** общий вид вкладки `Gap Control`.

- Схема расположения датчиков вокруг шпинделя (датчики 1–4 по периметру, датчик ОС на оси вращения) с текущими значениями по каналам;
- индикатор "Скрипт работает"/"Остановлен" и кнопки `Запустить`/`Перезапустить`/`Остановить` (`nc3_bep.py`);
- `Старт` — групповое измерение (все платы); `Стоп` — остановка измерения;
- `Старт (single)` — запуск одной платы (номер задаётся полем `board_num`);
- `Старт (CAPDAC)` — запуск одной платы с заданным `capdac_val`;
- таблица конфигурации каналов: номер, название, `CAN ID`, позиция датчика (1/2/3/4/ОС), флаг включения; кнопка `Сохранить`.

Если на схеме отображаются неизвестные `CAN ID`, их нужно сопоставить с датчиками и сохранить конфигурацию.

## 11. Вкладка `Settings`

Настройки нормализуются backend-узлом и сохраняются в `C:\NC3\settings.json`.

> **Место для скриншота:** вкладка `Settings`, основные настройки.

### 11.1 Основные настройки

- `Удалённое управление` — включение/отключение remote-mode (автосохраняется);
- `Поправка к углу наклона` — флаг использования поправки;
- `Запись исходных данных` — значение по умолчанию для raw-data;
- `Язык интерфейса` — русский/English;
- `Допуск готовности скорости, %` — порог достижения скорости в сценариях (по умолчанию 5 %);
- `Длительность файла данных, с` — длительность ручной записи по умолчанию;
- `Сохранение угла наклона` — не сохранять / записывать в заголовок файла протокола;
- режим ввода угла: DMS / °дес. / рад.

После изменений — кнопка "Сохранить настройки".

### 11.2 Расширенные настройки

Блок скрыт за замком и запрашивает пароль. **В текущей версии ПО фактическая проверка пароля отключена**: панель открывается сразу после нажатия кнопки разблокировки — это нужно учитывать организационно, доступ к расширенным настройкам должен регулироваться регламентом стенда, а не полем пароля.

- диапазон углов наклона (мин./макс. в DMS);
- диапазоны угловой скорости `high` и `low` (мин./макс. °/с);
- скорость переключения энкодеров (порог смены диапазона) и гистерезис;
- коэффициенты БЕП (K1–K5);
- круглограмма и калибровка энкодеров;
- **`KP[2]` — контур скорости**: показывает текущее значение, считанное из ELMO при подключении, и поле для записи нового значения в привод (`Записать в привод`). Параметр меняют при возникновении вибраций или нестабильной работы привода. Значения по умолчанию: `high` 5·10⁻⁷ (ранее использовалось 1·10⁻⁶), `low` 1·10⁻⁵. Новое значение отправляется приводу немедленно и **не сохраняется в `settings.json`** — при перезапуске ПО снова читает значение из ELMO.

Значения по умолчанию остальных параметров: `high` — от 1 угл. секунды/с до 20 °/с; `low` — от 10 до 360 °/с; порог переключения энкодера — 20 °/с; гистерезис — 5 °/с.

> **Место для скриншота:** расширенные настройки, блок `KP[2]` и диапазоны скорости.

## 12. Вкладки `Journal` и `Protocols`

### 12.1 `Journal`

Постоянный журнал событий, синхронизированный с `C:\NC3\logs\events.jsonl`.

- фильтры с счётчиком: Все / Инфо / Запись / Предупрежд. / Ошибки;
- путь к файлу журнала;
- кнопки `Обновить` и `Очистить` (очистка перезаписывает файл журнала);
- таблица событий: время / тип (цвет) / текст сообщения.

> **Место для скриншота:** вкладка `Journal`.

### 12.2 `Protocols`

Просмотр файлов из `C:\NC3\protocols` и связанных data-файлов из `C:\NC3\data`.

- список файлов с датой и размером (от новых к старым), метка "Протокол открыт" у активного файла;
- при выборе файла — просмотр содержимого в правой панели;
- при переходе к data-файлу — просмотр с инструментами построения графика: переключатель `Тики`/`°дес.`, кнопка `Построить`, `Приблизить`/`Отдалить`/`Сброс`, масштабирование колесом мыши, панорамирование мышью, кнопка "К протоколу".

График строится только после нажатия `Построить`. При менее двух точек в файле график недоступен.

> **Место для скриншота:** вкладка `Protocols` с графиком data-файла.

## 13. Типовые операции оператора

### 13.1 Подготовка к ручному воспроизведению скорости

1. Открыть Dashboard, перейти на `Angular Speed Control`.
2. Проверить строку статуса: `SR` — "Ошибок нет"; диапазон — нужный.
3. Включить двигатель (`Включить`) и дождаться `SO=1` — "Готов".
4. Если "Инициализация не проведена" — нажать `Drive Init` (выполнится оборот с поиском нулевой метки, раздел 7.2), дождаться "проведена".
5. В блоке "Параметры движения" задать `SP`, `AC`, `DC`, нажать "Применить параметры".
6. При необходимости открыть протокол.

### 13.2 Ручная запись результата

1. Нажать `Открыть протокол`.
2. Установить `Длительность записи`.
3. Включить `Запись исходных данных` при необходимости.
4. Задать скорость через `JP` или `JV`.
5. После стабилизации нажать `Запись`.
6. Дождаться окончания таймера.
7. Нажать `Закрыть протокол` по завершении.
8. Проверить результат на вкладке `Protocols`.

### 13.3 Выполнение сценария

1. Перейти на `Angular Speed Control`.
2. В блоке сценария включить флаг "Работа по сценарию" и ввести имя файла.
3. Убедиться, что протокол открыт (или откроется автоматически).
4. Нажать `Старт`.
5. Контролировать этап, уставку, факт и остаток выдержки.
6. При необходимости — `Пауза`, `Продолжить`, `STOP` или `Авария`.
7. После завершения проверить протокол (`Protocols`) и журнал (`Journal`).

### 13.4 Создание или изменение сценария

1. Перейти на `Scenario Manager`.
2. Нажать `Обновить`.
3. Выбрать файл или `+ Новый сценарий`.
4. Указать имя файла.
5. Заполнить таблицу шагов: скорость в °/с и выдержка в секундах.
6. Нажать `Сохранить`.

### 13.5 Управление наклоном

1. Перейти на `Tilt Control`.
2. Убедиться, что скрипт работает (индикатор "Скрипт работает").
3. Проверить текущий угол и режим.
4. Выбрать формат (DMS / deg / rad), ввести целевой угол.
5. Нажать `Установить`.
6. В ручном режиме контролировать состояние тормоза.

### 13.6 Работа с БЕП

1. Перейти на `Gap Control`.
2. Проверить статус скрипта — при необходимости `Запустить`.
3. Для группового измерения: `Старт`.
4. Для одной платы: задать `board_num`, нажать `Старт (single)`.
5. Для запуска с CAPDAC: задать `board_num`, `capdac_val`, нажать `Старт (CAPDAC)`.
6. По завершении: `Стоп`.
7. При изменении конфигурации каналов: `Сохранить`.

### 13.7 Просмотр журнала и протоколов

1. Для журнала — перейти на `Journal`, выбрать фильтр, нажать `Обновить`.
2. Для протоколов — перейти на `Protocols`, выбрать файл из списка.
3. Если строка содержит data-файл — кликнуть для перехода.
4. Выбрать режим (`Тики`/`°дес.`) и нажать `Построить`.

| Сообщение / состояние | Действие оператора |
|---|---|
| Протокол открыт | Продолжить измерения или закрыть протокол после окончания работы |
| Протокол закрыт | Открыть протокол перед ручной записью |
| Запись активна / обратный отсчёт | Дождаться завершения таймера |
| Нет событий для выбранного фильтра | Сменить фильтр или нажать `Обновить` |
| Файлы протоколов не найдены | Проверить, был ли протокол открыт; проверить каталог `C:\NC3\protocols` |
| График не построен | Нажать `Построить` |
| В файле данных нет точек для графика | Проверить режим записи исходных данных и длительность записи |
| `Инициализация в процессе` | Не отправлять конфликтующие команды до завершения; при необходимости прервать — `STOP`/`Выключить` (раздел 7.4) |
| `Инициализация проведена` | Продолжить работу |
| `Инициализация не проведена` / ошибка | Остановить работу, проверить `SR` и журнал |
| `Инициализация привода прервана оператором` | `Drive Init` был остановлен командой `STOP`/`Выключить` во время выполнения; при необходимости запустить заново |
| Смена разрешения невозможна | Выключить двигатель (`MO=0`, `SO=0`) и повторить |
| `Drive Init: required after resolution switch` | Запустить сценарий (выполнит автоматически) или вручную включить двигатель и нажать `Drive Init` |
| Сценарий: пауза | Нажать `Продолжить` или `STOP` после проверки состояния |
| Сценарий: Авария | Устранить причину, проверить привод; затем продолжить или завершить |
| `Speed reach timeout` | Проверить параметры ускорения, диапазон, состояние привода |
| `SR error: Код N: ...` | Действовать по таблице кодов `SR` в разделе 15 |
| `SR: errors cleared` | Продолжить работу |
| `Аварийная остановка: SO не стал = 1 за 30 с` | Проверить `SR`, цепь STO, питание привода |
| `Motion did not complete within ... ms` | Проверить ось на предмет препятствий; проверить `HM[3]`/`HM[4]`/`HM[5]`, если ошибка при `Drive Init`; повторить инициализацию |
| `ELMO отклонил команду "..."` | Проверить параметры и состояние привода |
| Привод не отвечает | Проверить питание ELMO и сеть `192.168.1.2`; ПО восстановит связь автоматически |
| Удалённый режим включён | Убедиться, кто является владельцем управления; помнить про раздел 4.1 (какая кнопка остановки доступна) |
| UI заблокирован | На удалённом клиенте нажать `Взять управление`; на локальном — только `E-stop`/`СТОП` |
| Скрипт работает (БУН/БЕП) | Обмен идёт, продолжать работу |
| Скрипт остановлен / ошибка | Нажать `Запустить` или `Перезапустить` на вкладке `Tilt Control`/`Gap Control` |
| Неизвестные CAN ID | Сопоставить ID с каналами датчиков и сохранить конфигурацию |

## 15. Обработка ошибок привода ELMO

Раздел составлен по документу "Рекомендации к разработке ПО для центрифуги с изменяемым направлением оси вращения НЦ-3/2" и текущей реализации ПО.

### 15.1 Где оператор видит ошибки

- Строка статуса `Angular Speed Control`: чип `SR` (зелёный/красный) с расшифровкой кода.
- Вкладка `Monitoring`: чипы состояния в строке вверху страницы.
- Вкладка `Journal`: события типа Ошибки и Предупрежд. Изменение `SR` фиксируется автоматически.
- Блок сценария: поле последней ошибки.

`SR` опрашивается циклически (~1 раз в секунду в составе фонового опроса состояния); ошибка появляется в интерфейсе с задержкой не более 1–2 секунд.

### 15.2 Коды ошибок усилителя (биты 0–3 регистра SR)

Запуск двигателя возможен только при коде 0.

| Код | Расшифровка | Причина | Действия оператора |
|---|---|---|---|
| 0 | Ошибок нет | Норма | Работа разрешена |
| 3 | Undervoltage | Силовое напряжение ниже нормы | Остановить; проверить питание привода; ответственный сверяет `AN[6]` |
| 5 | Overvoltage | Силовое напряжение выше нормы | Остановить; проверить питание привода; `AN[6]` |
| 7 | Safety / STO | Разомкнута цепь STO: нет +24 В на STO1/STO2; связано с давлением аэростатики | Проверить подачу воздуха, цепь безопасности; до восстановления STO двигатель не запустить |
| 9 | Sensor error | Неисправность датчика угла или подключения | Остановить; проверить кабели ДУ; повторить `Drive Init` |
| 11 | Short Protection | Ток превысил порог КЗ фаза-фаза/фаза-земля | Не перезапускать; отключить питание, вызвать ответственного за электрооборудование |
| 12 | Abort | Активны переключатели прерывания | Проверить внешние блокировки |
| 13 | Перегрев привода | Температура контроллера выше допустимой | Выключить двигатель, дать остыть; проверить охлаждение |
| 14 | Перегрев двигателя | Температура двигателя выше допустимой | Выключить двигатель, дать остыть; проверить нагрузку |
| 15 | Дополнительный Abort | Дополнительный сигнал прерывания | Проверить внешние цепи блокировки |

### 15.3 Автоматические защитные действия ПО

- **Таймаут готовности усилителя.** После `MO=1` ожидание `SO=1` не более 30 с. При таймауте — `ST` и `MO=0`, запись в журнал.
- **Таймаут контрольного оборота `Drive Init`.** Не менее 360 секунд (6 минут) на весь оборот с поиском нулевой метки (раздел 7.4). Если оборот не завершился — `ST` и `MO=0`, `Drive Init: failed` в журнале.
- **Отклонённые команды.** При ответе `?` от привода — предупреждение в журнале. Повторяющиеся отказы означают некорректные параметры.
- **Потеря связи.** После 3 пропусков ответа подряд — offline; ПО периодически восстанавливает связь. Команды в момент потери нужно повторить.
- **Авария сценария.** Кнопка `Авария` — `ST` и отмена записи; сценарий можно продолжить после устранения причины.
- **Прерывание `Drive Init` оператором.** `STOP`/`Выключить` во время инициализации немедленно останавливают её и помечают как ошибку (раздел 7.4) — это штатное поведение, а не сбой ПО.

### 15.4 Порядок действий при ошибке запуска двигателя

1. Убедиться: `SR` = "Ошибок нет" (код 0). Иначе — устранить по таблице 15.2.
2. Нажать `Включить` (`MO=1`).
3. Дождаться `SO=1` — "Готов" (может занимать до десятков секунд).
4. При защитной остановке: проверить `SR` и журнал. Ответственный персонал считывает `EE[5]` и `MF` через EAS II.
5. После устранения причины повторить включение. `MF` сбрасывается автоматически при `MO=1`; `EC` сбрасывается командой `EC=0` в составе `Drive Init`.

### 15.5 Диагностические параметры для ответственного персонала

| Параметр | Назначение | Примечание |
|---|---|---|
| `SR` | Статус-регистр: биты усилителя, MO/SO, STO, режим движения | Расшифровка битов 0–3 — таблица 15.2 |
| `EC` | Код последней ошибки по "P_Drive General Error List" | Сброс: `EC=0` в полном `Drive Init` |
| `MF` | Код причины отключения двигателя (bit field) | Сбрасывается при каждом `MO=1` |
| `EE[5]` | Код ошибки неудачного запуска | Читается через EAS II |
| `AN[6]` | Фактическое силовое напряжение | Проверять при Undervoltage/Overvoltage |
| `HM[1]` | Флаг активного поиска нулевой метки | Должен вернуться в `0` по завершении оборота `Drive Init`; если не вернулся — см. раздел 7.2 |
| `HM[7]` | Смещение нулевой метки, применённое при последнем поиске | Диагностика для ответственного персонала, не выводится в UI |

### 15.6 Восстановление параметров привода

При некорректных параметрах (привод отклоняет команды) — восстановить конфигурацию из FLASH. Процедура ответственного персонала, не из операторского UI:

1. Выключить двигатель (`MO=0`).
2. Сбросить параметры к заводским значениям (`SR`).
3. Загрузить сохранённую конфигурацию командой `LD`.
4. Убедиться в работоспособности привода.

Команду `SV` не использовать до проверки параметров: некорректное сохранение во FLASH — ошибка `BAD DATABASE` (`CD[1]`). Загрузить параметры через EAS II ("Parameters" → "Download Textual Parameters file to Drive"), затем `SV`.

После любого восстановления: `БПП` при выключенном двигателе, затем `Drive Init`.

### 15.7 Особенности ошибок канала БУН

- При потере пакетов > 1,5 с — угол и состояние на `Tilt Control` перестают обновляться. Нажать `Перезапустить` или проверить сеть и скрипт `nc3_bun.py`.
- `Release` — аварийное действие: мгновенная остановка с отключением драйверов наклона.
- При ошибке Safety/STO тормоз внешней оси (`OL[2]`) сохраняет последнее состояние; перед продолжением работы проверить состояние тормоза на `Tilt Control`.

## 16. Ограничения текущей версии

- при полном redeploy Node-RED серверный таймер активной записи может быть сброшен — активную запись следует завершать штатно до обслуживания flow;
- проверка пароля расширенных настроек в текущем UI-шаблоне отключена, доступ должен регулироваться организационно (раздел 11.2);
- значение `KP[2]` в расширенных настройках не сохраняется в `settings.json` — при перезапуске ПО читает текущее значение из привода заново;
- runtime-сценарии из `C:\NC3\scenarios` не синхронизируются с репозиторием автоматически;
- индикатор давления на вкладке `Monitoring` в текущей версии — фиксированная заглушка;
- диагностические коды `EC`, `MF`, `EE[5]`, `AN[6]`, `HM[7]` не отображаются в операторском интерфейсе; их чтение выполняется ответственным персоналом через Elmo Application Studio (раздел 15.5);
- кнопка `Продолжить` сценария повторяет текущий шаг с начала, остаток выдержки не восстанавливается;
- кнопка `STOP` на вкладке `Angular Speed Control` и кнопка `Авария` в блоке сценария не гарантированы к прохождению при активном удалённом управлении и заблокированном локальном UI — используйте `E-stop`/`СТОП` (раздел 4.1).
